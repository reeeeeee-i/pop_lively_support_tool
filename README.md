# pop_lively_support_tool

pop'n music Lively 専用のサポートツールです。  
beatmania IIDX INFINITAS 向けツール [inf_daken_counter_obsw](https://github.com/dj-kata/inf_daken_counter_obsw) を参考に、pop'n music Lively 専用として新規開発しました。

## 機能

- プレー中の判定内訳（COOL / GREAT / GOOD / BAD）をリアルタイム集計
- 打鍵数（COOL + GREAT + GOOD の合計。BAD は見逃し扱いで含めない）を表示
- ゲーム画面の自動検出（タイトル / ステータス / チケット / キャラセレクト / 選曲 / オプション / プレー / リザルト / 終了画面）
- 曲名・難易度区分・使用オプションの自動読み取り
- 譜面ごとのベスト・前回スコアの表示、リザルトでのベスト比較（NEW BEST 表示）
- 統計（日・週・月別の打鍵数 / プレー数のグラフ、レベル別の成績、曲別のスコア・判定内訳の推移）とセッションサマリー
- 曲を特定できなかったときの手動選択と学習、曲リストの更新、バックアップ・復元・インポート、認識診断
- リザルト画面からのスコア自動記録（リタイアしたプレーを記録しない設定も可）、スコア履歴の閲覧・修正、CSV 出力
- リザルト画面のスクリーンショット保存（毎回 / 自己ベスト / FULL COMBO / PERFECT から条件を複数選択、PNG / JPEG）
- OBS WebSocket 連動（録画・配信の開始・停止、シーン切り替え、ソースの表示切り替え）
- ゲーム画面キャプチャ方式: 直接取得 (DXCAM) / 旧直接取得 / OBS WebSocket 経由
- フルスクリーン・ウィンドウモード両対応

## 動作環境

- OS: Windows 10 / 11
- pop'n music Lively

> **注意**: `popnlively.exe` のプロパティ（互換性タブ）で「全画面表示の最適化を無効にする」にチェックを入れないでください。
> チェックを入れると、ゲーム画面の取り込み（直接取得・OBS のどちらでも）が重くなり、動作が遅くなることがあります。

## 使い方

### 起動

1. `pop_lively_support_tool.exe` を実行する
2. pop'n music Lively を起動する（どちらを先に起動してもかまいません）
3. ゲーム画面が自動で検出され、メインウィンドウの「現在のモード」が「ゲーム画面を待機中...」から、タイトル・選曲中・プレー中などの画面名に変わる

あとは普段どおりプレーするだけで、打鍵数のカウントとスコアの記録が自動で行われます。ツール側の操作は不要です。

ゲーム画面が検出されない場合は、メニュー → ファイル → 設定 の「ゲーム画面取得」で取得方式を切り替えてください（「[設定](#設定)」を参照）。

### メインウィンドウ

| 表示 | 内容 |
|-----|------|
| 現在のモード | 検出中のゲーム画面（タイトル / ステータス / チケット / キャラセレクト / 選曲中 / オプション / プレー中 / リザルト / ロード中 / 終了画面）。検出できていない間は「ゲーム画面を待機中...」 |
| 起動時間 | ツールを起動してからの経過時間 |
| 本日の打鍵数 | 今日の打鍵数の合計。プレー中もリアルタイムに増える。日付が変わると 0 から数え直す |
| 最後にプレイした曲 | 直近にプレーした曲名と難易度区分 |
| 曲を選択... ボタン | 曲を特定できなかったときだけ表示される。押すと曲の選択ダイアログが開き、選んだ曲を現在のプレー曲にする（記録済みのスコアが曲不明のままなら、その曲に付け替える）。プレー画面で読み取った曲名は読み替えとして学習し、次回から自動で認識する |
| この譜面の成績 | プレー画面で曲を特定すると「ベスト / 前回 / プレー回数」（初めてなら「初プレー」）を表示。リザルトの記録後は、今回のスコアと前のベストとの差を表示し、自己ベスト更新なら「NEW BEST!」と黄色で表示する |

「本日の打鍵数をリセット」ボタン（またはメニュー → ファイル → 本日の打鍵数をリセット）で、本日の打鍵数を 0 に戻せます。記録済みのスコアは消えません。

ウィンドウ下部のステータスバーには、ゲーム画面の取得状況と OBS の接続状態（OBS 接続中 / OBS 未接続）が表示されます。

### プレー中の動作

- **オプション画面**: 使用オプション（ハイスピード・RANDOM など）を読み取り、以降のスコアに記録する
- **プレー画面**: 曲名と難易度区分を特定し、判定の累計値から打鍵数を数える
- **リザルト画面**: スコア・判定内訳・コンボを読み取り、数値が安定した時点でスコアを 1 件記録する。設定した保存条件を満たしていれば、リザルト画面のスクリーンショットも保存する

リザルト画面に到達しなかった曲（リトライなど）は、スコアは記録されませんが、打鍵数には加算されます。

リタイアしたプレー（リザルト画面に「Retire」と表示されるプレー）は、既定ではスコアを記録します。設定の「retire 時は保存しない」を有効にすると、スコアは記録せず（スクリーンショットも保存せず）、打鍵数だけを本日の打鍵数に加算します。

### スコアの確認・修正

メニュー → スコア → スコア履歴 / CSV表示 で、記録したスコアの一覧を開きます。

- **検索**: 右上の検索欄（Ctrl+F）で、表示中の列から部分一致で絞り込む。空白区切りで AND 検索
- **列の調整**: 「表示列」ボタン、または列見出しの右クリックで列の表示・非表示を切り替える。列見出しのドラッグで並び替え、境界のドラッグで幅を変更できる
- **修正**: 行をダブルクリック（または右クリック →「編集...」）すると詳細を開き、曲・難易度区分・スコア・オプションなどを修正できる。曲を特定できず `Unknown` で記録されたスコアも、「曲を変更...」で正しい曲に直せる
- **削除**: 行を選択して右クリック →「削除」。複数行をまとめて削除できる
- **CSV 出力**: 「CSVエクスポート...」（またはメニュー → データ → CSVファイルを出力）でスコアを CSV に書き出す。「CSVファイルを外部アプリで開く」で、書き出した CSV を表計算ソフトなどで開く

- **絞り込み**: 検索欄の下の条件で、難易度区分・レベル範囲・クリア種別（FULL COMBO / PERFECT / FULL COMBO 以外）・期間（今日 / 直近7日 / 直近30日 / 今月）・「各譜面のベストのみ」を組み合わせて絞り込める（検索欄の文字列とも併用できる）。「条件をクリア」で解除
- **スコア推移**: 行を右クリック →「この譜面のスコア推移を表示...」で、その譜面の統計（曲別の推移）を開く

- **曲の修正と学習**: 詳細画面で曲を変更すると、プレー画面で読み取った曲名を読み替えとして学習する。同じ読み取りで `Unknown` になっていた他のスコアも、まとめて直る

### データの管理

メニュー → データ から次の操作ができます。

| 項目 | 内容 |
|-----|------|
| 曲リストをURLから更新 | 設定の「曲リストの取得先 URL」（既定は、このリポジトリの `main` ブランチの `popn_music_list.json`）から曲リストを取得して曲テーブルを更新する。取得前に確認を出し、「はい」と答えたときだけ接続する。**開発者の署名を検証できた曲リストだけ**を取り込む（「[セキュリティ](#セキュリティ)」を参照） |
| 曲リストをファイルから更新 | `popn_music_list.json` 形式の JSON を選んで曲テーブルを更新する。同じフォルダに `<ファイル名>.sig` があれば署名を検証し、不正なら取り込まない。署名が無いファイルは、確認のうえで取り込める |
|  | どちらも、同じ曲は更新、新曲は追加する。更新後、これまで `Unknown` だったスコアを保存済みの読み取り結果で照合し直す |

| CSVファイルを出力 / CSVファイルを開く | スコア履歴を CSV に書き出す / 書き出した CSV を既定のアプリ（表計算ソフトなど）で開く |
| CSVからスコアをインポート | 出力した CSV（旧形式を含む）からスコアを取り込む。プレー日時とスコアが同じ記録は飛ばす |
| 認識診断 | 下記 |

### 自動更新

メニュー → ヘルプ → 更新を確認 で、GitHub の最新リリースを確認します。新しいバージョンがあれば更新内容を表示し、「更新して再起動」でダウンロード・更新・再起動までを自動で行います（設定で「起動時に新しいバージョンを確認する」を有効にすると、起動のたびに自動で確認します）。

- **開発者の署名を検証できた更新だけ**を適用します（署名が無い・不正なリリースは使いません）。このリポジトリのリリース以外からはダウンロードしません（「[セキュリティ](#セキュリティ)」を参照）
- 更新中にアプリが終了し、終了後にファイルを上書きして再起動します。設定（`config.json`）・スコア（`popn.db`・CSV）・ログ・スクリーンショット・診断データ・バックアップは上書きしません
- 更新の結果は `log/update.log` に残ります
- アプリのフォルダに書き込めない場合や、ソースから実行している場合は自動更新できません（リリースページを開く案内が出ます）
- 現在のバージョンは、メニュー → ヘルプ → バージョン情報 で確認できます

### リリースの作り方（開発者向け）

自動更新は、GitHub の最新のリリース（プレリリースを除く）を見ます。次の形にしてください。

- タグ名は `pyproject.toml` の version と同じ `YYMMDD`（同日の再リリースは `YYMMDD.N`）にする。タグ名で新旧を比べるので、`261004_初版` のように形式が違うタグは新しい版として扱われない
- 添付ファイルは、`pop_lively_support_tool` で始まる `.zip`（例: `pop_lively_support_tool_261101.zip`）と、その署名ファイル `.zip.sig`（`tools/sign_release.py sign-release` で作る）の 2 つにする。zip の中身は `build.bat` の出力（`dist\pop_lively_support_tool`）で、`pop_lively_support_tool.exe` が zip 直下か、その 1 階層下にあること。**署名ファイルが無いリリースは、アプリが更新に使いません**
- ビルドは `pyproject.toml` を exe と同じフォルダにコピーします（アプリが自分のバージョンを読むため）
- 自動更新が使えるのは、この機能を含むバージョン以降です。それより前のバージョンを使っている人は、一度手動で更新してもらう必要があります

### 曲リストの配信（開発者向け）

曲リストは、このリポジトリの `popn_music_list.json`（`main` ブランチ）をそのまま配信元にしています。新曲を反映するときは、次の手順です。

1. `generate_music_list.py` で JSON を作り直す
2. `python tools/sign_release.py sign-music popn_music_list.json` で署名する（JSON と `.sig` は `.gitattributes` で改行コードを変換しない設定にしてあります。署名したバイト列と、配信されるバイト列を一致させるためです。署名後に JSON を編集し直さないでください）（`popn_music_list.json.sig` ができる。通し番号は自動で 1 増える）
3. JSON と `.sig` を**一緒に**プルリクエストにして、`main` にマージする（`main` は保護されているため直接プッシュはできません）

アプリは `https://raw.githubusercontent.com/reeeeeee-i/pop_lively_support_tool/main/popn_music_list.json` を取得するので、反映まで数分かかることがあります。各曲の `music_id` は変えないでください（スコアとの紐づけに使っています）。

### セキュリティ

曲リストとツール本体の更新は、次の仕組みで保護しています。実装は `src/signing.py`・`src/ed25519.py`・`src/secure_http.py`・`src/music_list_fetch.py`・`src/updater.py`、テストは `tests/test_security.py` です。

**署名（改ざん・なりすましの防止）**

- 配布物（曲リストの JSON、ツール本体の zip）は、開発者だけが持つ秘密鍵で **Ed25519 署名**します。アプリは `src/trusted_keys.py` の公開鍵で検証し、署名を検証できないものは使いません。GitHub のアカウントやリポジトリ、リリース、通信路が侵害されても、秘密鍵が無ければ偽物を配れません
- 署名は、配布物の SHA-256・サイズ・名前・バージョン（曲リストは通し番号）を束ねたものに付けます。1 バイトでも変わると検証に失敗します
- 署名の種類（曲リスト / リリース）も署名に含むので、曲リストの署名をリリースに流用することはできません
- 署名済みの古いバージョンを新しいものとして配る攻撃（ロールバック）も防ぎます。リリースは署名内のバージョンとタグの一致を、曲リストは署名の通し番号が取り込み済みの最大値より小さくないことを確認します
- 署名の実装は標準ライブラリだけの純 Python で、RFC 8032 のテストベクターと、別実装（cryptography）との突き合わせで確認しています

**通信**

- https のみ。証明書とホスト名を検証し、TLS 1.2 以上を要求します。リダイレクトも https のみで、ツール本体の更新は GitHub のホストへのものだけを許可します
- 応答のサイズに上限があり（曲リスト 20MB・更新 zip は署名に書かれたサイズ）、圧縮された応答は受け取りません
- 取得は、利用者が「はい」と答えたとき（または設定で起動時の確認を有効にしたとき）だけ行います

**取り込む内容の検証**

- 曲リストは、署名の検証のあとに、項目の型・長さ・数値の範囲・制御文字・`music_id`（UUID）の形式と重複を検証し、既知の項目だけを取り込みます。曲リストの更新の前には、データベースを `backup` フォルダへ自動で保存します（最新 5 件）
- 更新 zip は、展開先の外への書き出し（`..`・絶対パス・ドライブ指定・`:`）、シンボリックリンク、展開後サイズの過大、ファイル数の過大を拒否します。ダウンロードしたファイルが署名のハッシュ・サイズと違えば破棄します
- 更新用バッチに埋め込むフォルダのパスに、`%` `"` `&` `^` `|` `!` や改行などが含まれる場合は、命令の混入を防ぐため自動更新を行いません

**署名の手順（開発者向け）**

1. 初回だけ、鍵を作ります。秘密鍵は `~/.pop_lively_support_tool/signing_key.hex` に作られ、自分だけが読める権限になります。**リポジトリに入れず、別の場所にもバックアップを取ってください**（失くすと、以後の配布物に署名できません）

   ```bash
   python tools/sign_release.py genkey
   ```

   表示された公開鍵の行を `src/trusted_keys.py` の `TRUSTED_PUBLIC_KEYS` に追加し、その鍵で署名した版を配布します
2. 曲リスト: `python tools/sign_release.py sign-music popn_music_list.json`
3. リリース: `build.bat` で作った `dist\pop_lively_support_tool` を zip にして、`python tools/sign_release.py sign-release <zip> --tag <version>` で署名し、zip と `.sig` の両方をリリースに添付します
4. 署名の確認: `python tools/sign_release.py verify <ファイル>`

鍵を更新するとき（漏れていない場合）は、新しい公開鍵を `trusted_keys.py` に追加したバージョンを旧い鍵で署名して配布し、全員が更新し終えてから新しい鍵での署名に切り替えます。旧い鍵はその後に削除してください。**秘密鍵が漏れた（疑いがある）ときは、その鍵で署名した更新はもう安全ではありません。** 新しい鍵を埋め込んだバージョンを、利用者に手動で入れ直してもらってください。

**注意**

- 公開鍵をアプリに埋め込む仕組みなので、**署名の鍵を最初に配るバージョン（この機能を含むバージョン）は、利用者が手動で入手する必要があります**。それ以降の更新は、署名で守られます
- 署名の検証に使う公開鍵が `trusted_keys.py` に無いときは、曲リストの取得・自動更新のどちらも拒否します（安全側に倒します）
- 「ファイルから更新」で署名の無い曲リストを取り込めるのは、利用者自身が内容を確認できる、手元のファイルを使う場合のためです。入手元が信頼できないファイルは取り込まないでください

### 認識診断

設定の「読み取りに失敗した画面を診断データとして保存する」を有効にすると、次の画面を `diagnostics` フォルダに保存します（確定していないデータは最新の 60 件まで）。

- 曲を特定できなかったプレー画面
- 読み取りに不確かな点があったリザルト画面
- プレー中に読んだ判定内訳が、リザルトの値と食い違ったプレー画面

メニュー → データ → 認識診断 で、画像を見ながら正解値を入力して「正解を確定」を押します（判定内訳の入力欄は、リザルトの値が初期値）。曲名は、正解の曲を選んで確定すると読み替えとして学習します。
確定した判定内訳・リザルトの値は、`tools/build_judge_templates.py` / `tools/build_digit_templates.py` を実行するとサンプルとして自動で使われます（`SAMPLES` へ手で追加する必要はありません）。配布版の `diagnostics` フォルダを使うときは、環境変数 `DIAGNOSTICS_DIR` でそのフォルダを指定します。

### 統計・セッションサマリー

メニュー → スコア → 統計 で、記録したスコアを集計して表示します。

| タブ | 内容 |
|-----|------|
| 打鍵数・プレー数 | 日別 / 週別（月曜始まり）/ 月別の打鍵数またはプレー数の棒グラフ。直近の期間数（または全期間）を選べる。棒にマウスを乗せると内訳を表示 |
| レベル別 | レベルごとのプレー数・プレー済み譜面数・FULL COMBO / PERFECT 譜面数・ベスト平均・最高スコア。難易度区分で絞り込める |
| 曲別の推移 | 譜面（曲 + 難易度区分）を選ぶと、スコアの折れ線グラフ（黄色の点 = ベスト更新）、判定内訳（COOL / GREAT / GOOD / BAD）の積み上げ棒グラフ、プレー履歴の表を表示 |

> FULL COMBO / PERFECT は BAD・GOOD の数で判定します。リザルトの「Retire」表示は記録に残していないため、リタイアしたプレーも BAD が 0 なら FULL COMBO として数えます。

メニュー → スコア → セッションサマリー で、ツールを起動してからの成績（プレー数・打鍵数・平均スコア・FULL COMBO / PERFECT 数・初プレー譜面数・自己ベスト更新の一覧）を表示します。クリップボードへコピーもできます。

サマリーは 1200x675 の画像（カード）としても出力できます。
別のタブ「リザルト画像」では、保存したリザルトのスクリーンショットから使うものを選び（対象の期間は「今回のセッション」（既定）/「本日」/「昨日から」/「直近 7 日」から選ぶ。日付をまたいだセッションでも、前日分のリザルトが対象になる。期間内のリザルトは既定ですべてチェックされ、一覧のチェックで入れ替えられる。画像の見出しには、日付をまたぐ場合は期間を表示する）、2（横）x 4（縦）で並べた**リザルトだけの画像**を作れます。1 枚の画像に並べられるのは 8 枚までなので、それを超える場合は古い順に 8 枚ずつ、複数の画像に分けて生成します。「リザルト画像を生成」を押すとプレビューが表示されます。「n / m 枚目」で表示する画像を切り替え、「表示中の画像をコピー」でクリップボードにコピーするか、「表示中の画像を保存...」「すべて保存...」で PNG に保存できます（X は 1 回の投稿に最大 4 枚の画像を付けられます）。リザルトのスクリーンショットは、設定の保存条件で保存したものが対象です。

| ボタン | 内容 |
|-------|------|
| サマリー画像を保存... | サマリーのカード画像を PNG で保存する |
| サマリー画像をコピー | サマリーのカード画像をクリップボードにコピーする |
| X にポスト | サマリー画像をクリップボードにコピーし、投稿テキスト入りの X の投稿画面をブラウザで開く。X の投稿画面には画像を自動で添付できないため、入力欄で Ctrl+V を押して画像を貼り付けてから投稿する。リザルト画像も付けるときは、「リザルト画像」タブでコピーしてから、もう一度貼り付ける |
ツールの終了時には、プレーがあればこのサマリーを `popn_session_log.csv`（スコア CSV と同じフォルダ）に 1 行追記します。

### ソースから実行する場合

[uv](https://docs.astral.sh/uv/) で仮想環境を作成してから実行します。

```bash
uv sync
```

- 実行: `run.bat`（`.venv` の Python で `pop_lively_support_tool.pyw` を起動）
- exe のビルド: `build.bat`（`dist\pop_lively_support_tool\` に出力）

## 設定

メニュー → ファイル → 設定 から以下を変更できます。

| 設定項目 | 説明 |
|---------|------|
| ゲーム画面取得 | 直接取得 (DXCAM) / 直接取得 (旧方式) / OBS WebSocket 経由 |
| 常に全モニターを対象にする | 旧直接取得で、常に全モニターを対象に画面を取り込む（既定は無効） |
| 常に最前面表示する | ウィンドウを常に最前面に表示する |
| Lively の CPU 割り当てを 1 コアにする | Lively のロード時間短縮。起動を検出したら、使用率が最小の CPU だけを割り当て、優先度を「高」にする（既定は無効） |
| ログの最大容量 | `log` フォルダ全体の容量の上限（MB、既定は 20）。上限を超えると古いログから自動的に削除する |
| retire 時は保存しない | 「スコア保存時の条件」。リタイアしたプレー（リザルト画面に「Retire」と表示されるプレー）のスコアを記録しない。打鍵数は本日の打鍵数に加算する（既定は無効） |
| リザルトのスクリーンショット: 保存条件 | 毎回 / 自己ベスト / FULL COMBO / PERFECT から複数選択（既定はすべて未選択 = 保存しない）。スコアを記録したとき、チェックした条件のいずれかを満たしていればリザルト画面を保存する。「自己ベスト」はリザルト画面に「NEW RECORD!」が表示され、BEST SCORE の差分が + のとき（差分が読み取れないときは「NEW RECORD!」のみで判断）、「FULL COMBO」は BAD が 0、「PERFECT」は GOOD と BAD が 0 のとき。リタイアしたプレーは FULL COMBO / PERFECT として扱わない |
| リザルトのスクリーンショット: 保存先フォルダ | 保存先（既定は `result_screenshots`）。ファイル名は `日時_曲名_難易度_スコア.png`（JPEG のときは `.jpg`） |
| リザルトのスクリーンショット: 保存形式 / JPEG 圧縮率 | PNG / JPEG（既定は PNG）。JPEG のときはスライダーで圧縮率（品質 10～100、既定 85）を指定できる。1920x1080 でのファイルサイズの目安を横に表示する |
| 起動時に新しいバージョンを確認する | 起動の少しあとに、GitHub のリリースで新しいバージョンを確認する（既定は無効）。新しいバージョンがあるときだけ案内を表示する |
| 曲リストの取得先 URL | 「曲リストをURLから更新」で取得する URL（https のみ。空欄にすると既定に戻る） |
| 認識診断 | 読み取りに失敗した画面を診断データとして保存する（「[認識診断](#認識診断)」を参照） |
| OBS ホスト/ポート/パスワード | OBS WebSocket 接続先 |
| ゲームキャプチャソース名 | OBS WebSocket 経由時のソース名 |

## OBS 自動制御

ゲーム画面の切り替わりに合わせて、OBS の録画・配信・シーン・ソース表示を自動で操作できます。
メニュー → ファイル → OBS 制御設定 から設定します。

### 事前準備

1. OBS の「ツール → WebSocket サーバー設定」で WebSocket サーバーを有効にする
2. OBS 制御設定を開き、「OBS WebSocket 接続設定」にホスト・ポート・パスワードを入力する
3. 「OBS に再接続」を押し、接続できることを確認する（接続するとシーン一覧が読み込まれる）

### 制御ルールの追加

「制御ルールの追加」で次の項目を選び、「追加」を押します。追加したルールは「登録済み制御ルール」に並びます。

1. **アクション**: 実行する操作（下表）
2. **タイミング**: 実行するきっかけ（下表）
3. **シーン / ソース / 切り替え先シーン**: アクションに応じて必要なものだけ選べるようになる

| アクション | 説明 | 必要な指定 |
|----------|------|----------|
| シーン切り替え | OBS のシーンを切り替える | 切り替え先シーン |
| 録画開始 / 録画停止 | OBS の録画を開始・停止する | なし |
| 配信開始 / 配信停止 | OBS の配信を開始・停止する | なし |
| ソース表示 / ソース非表示 | 指定したシーン内のソースの表示を切り替える | シーン、ソース |

タイミングは、次の各画面の「表示」（その画面に入ったとき）と「終了」（その画面から出たとき）を選べます。

| 画面 | 表示 | 終了 |
|-----|------|------|
| タイトル画面 | タイトル画面表示 | タイトル画面終了 |
| ステータス画面 | ステータス画面表示 | ステータス画面終了 |
| チケット画面 | チケット画面表示 | チケット画面終了 |
| キャラセレクト | キャラセレクト表示 | キャラセレクト終了 |
| 選曲画面 | 選曲画面表示 | 選曲画面終了 |
| オプション画面 | オプション画面表示 | オプション画面終了 |
| プレー画面 | プレー開始 | プレー終了 |
| リザルト画面 | リザルト表示 | リザルト終了 |
| 終了画面 | 終了画面表示 | 終了画面終了 |

ルールを消すときは、一覧で行を選んで「選択行を削除」を押します（「すべて削除」で全ルールを削除）。
ルールの内容を変えたいときは、いったん削除してから追加し直してください。

設定例: プレー中だけ録画し、リザルトで専用シーンに切り替える

| タイミング | アクション | シーン |
|----------|----------|------|
| プレー開始 | 録画開始 | |
| プレー終了 | 録画停止 | |
| リザルト表示 | シーン切り替え | リザルト |

### その他の項目

| 項目 | 説明 |
|-----|------|
| 起動時シーンコレクション | OBS に接続したときに切り替えるシーンコレクション。「(変更しない)」なら切り替えない。ダイアログで選択した時点で OBS 側も切り替わる |
| OBS WebSocket 経由キャプチャ用ソース | ゲーム画面取得を「OBS WebSocket 経由」にしたときに読み取るソース。アクションで「ソース表示」か「ソース非表示」を選び、シーンとソースを選んで「このソースをゲームキャプチャソースとして設定」を押すと設定できる。「クリア」で解除 |
| シーン一覧を更新 | OBS 側でシーンやソースを変更したときに、選択肢を読み込み直す |

「OK」を押すと設定が `config.json` に保存され、OBS に再接続します。

> **注意**: ルールの追加・削除はその場で反映され、「キャンセル」で閉じても取り消されません（ファイルへの保存は「OK」を押したときか、設定ダイアログを保存したときです）。

## 判定読み取りの仕組み

プレー画面下部バーに表示される「BAD / GOOD / GREAT / COOL」の累計値を、
数字として読み取ります (`src/judge_reader.py`)。

- 数字は 4 桁固定で、先頭の 0 埋めは暗く、有効な桁だけが明るく表示されます。
  判定ごとの色（COOL: マゼンタ / GREAT: 橙 / GOOD: 赤 / BAD: シアン）で明るい桁だけを取り出し、
  テンプレート (`src/judge_templates.py`) と照合します。
- 累計値そのものを読むため、フレームを取りこぼしても打鍵数はずれません。
  累計値は増える一方なので、減った値や急に増えた値は読み誤りとして採用しません。
- リザルト画面を読めた時点で、その曲の分はリザルト画面の値に置き換えます
  （「retire 時は保存しない」でスコアを記録しなかった場合も同じです）。
  リザルトに到達しなかった曲（リトライなど）は、プレー中に読めた値を本日の打鍵数に加算します。
  曲の切り替わりは、累計値が 0 付近に戻ったことで判断します。

読み誤る数字が見つかった場合は、その画面のスクリーンショットと正解値を
`tools/build_judge_templates.py` の `SAMPLES` に追加して実行し、テンプレートを作り直します。

## 曲名・難易度区分の読み取りの仕組み

プレー画面上部の曲名バーから、プレー中の曲と難易度区分を特定します (`src/song_reader.py`)。

1. 黒地に白文字の曲名バーを検出し、曲名を Windows 標準 OCR (`Windows.Media.Ocr`) で文字列にする
2. OCR 結果を曲テーブル (musics) の曲名とあいまい照合して曲を特定する（多少の誤字は吸収）
3. 曲名バー右端の丸アイコンの色から難易度区分を判定する

| 難易度区分 | アイコンの色 |
|-----|-------|
| EASY | 青 |
| NORMAL | 緑 |
| HYPER | 橙 |
| EX | 赤〜ピンク |

レベルは特定した曲と難易度区分から曲テーブルを引いて求めます。

> **注意**: 日本語の OCR 言語パック（日本語版 Windows には標準で入っています）と `winrt-*` パッケージが必要です。
> 使えない環境では曲名は `Unknown` のまま記録されます。
> 同名曲（ウラ譜面・LIVE版・カバー等）は曲名だけでは区別できないため、その難易度の譜面がある Lively 収録曲を優先します。
> 特定できなかった場合は曲名バーの画像を `out/last_song_title.png` に保存します。

## 使用オプションの読み取りの仕組み

オプション画面から使用オプションを読み取ります (`src/option_reader.py`)。

### 設定を開いている間（右下の設定一覧）

1. こげ茶色のパネルに並ぶ 11 行（上から ハイスピード / ポップ君 / ゲージタイプ / GUIDE SE / RANDOM / JUDGE+ / HIDDEN / SUDDEN / OJAMA1 / OJAMA2 / AUTO。シンプル設定では上 4 行のみ）を、各行の下線を手がかりに検出する
2. 各行の文字を Windows 標準 OCR で文字列にし、オプションマスターの値に正規化する（多少の誤字は吸収）
3. OJAMA 行の先頭に黄色の「ずっと」があれば「OJAMA ずっと」を ON とする

### 設定を開いていない間（OptionSelect 画面のオプションアイコン）

| 項目 | 読み取り方法 |
|-----|-------|
| ハイスピード | bpm 行の「150 × 2.9 = 435」を OCR で読む |
| ポップ君 / ゲージタイプ / RANDOM / JUDGE+ / AUTO | アイコンの絵柄をテンプレート (`src/option_templates.py`) と照合 |
| HIDDEN / SUDDEN | アイコン内の数字を 1 文字ずつテンプレートと照合 |
| GUIDE SE | ON / OFF のみ判別（「ON 大」と「ON 小」は同じ絵柄のため区別不可。ON の場合、直前の値が ON ならそれを引き継ぎ、OFF なら「ON 大」とする） |
| OJAMA1 / OJAMA2 | OFF のみ判別（設定中は番号しか表示されず、種類が分からない） |

テンプレートは `tools/build_option_templates.py` で、設定値の分かっているスクリーンショットから生成します。
読めないアイコンや数字が見つかったら、スクリーンショットと設定値を `SAMPLES` に追加して再実行してください。

どちらの場合も、同じ内容が続けて読めた時点で現在の使用オプションに反映し、以降のリザルトで記録されます。読めなかった項目は直前の値を引き継ぎます。

## スコア管理・データベース (SQLite & CSV)

- **曲マスター管理 (musics テーブル)**:
  - `popn_music_list.json` からインポートされ、各楽曲に一意の **UUID** (`music_id`) が付与されます。
- **スコア管理 (scores テーブル)**:
  - リザルト画面で検出されたスコアを記録します。
  - スコアテーブル側には曲名やレベルなどの曲情報は持たず、**UUID (`music_id`)** を用いて曲マスターテーブルと結合して管理されます（レベルは難易度区分と曲テーブルから自動導出）。
  - 保存される項目: 難易度区分、SCORE、COOL、GREAT、GOOD、BAD、COMBO、プレー日時、および以下の **13 種類のオプション**:
    - **HI-SPEED** (`hispeed`: デフォルト値 `"1.0"`)
    - **POP-KUN** (`popkun`)
    - **GAUGE TYPE** (`gauge_type`)
    - **GUIDE SE** (`guide_se`)
    - **RANDOM** (`random`)
    - **JUDGE+** (`judge_plus`)
    - **HIDDEN** (`hidden`)
    - **SUDDEN** (`sudden`)
    - **OJAMA1** (`ojama1`)
    - **OJAMA2** (`ojama2`)
    - **OJAMA1 ずっと** (`ojama1_zutto`)
    - **OJAMA2 ずっと** (`ojama2_zutto`)
    - **AUTO** (`auto`)
- **オプションマスター (option_masters テーブル)**:
  - 各オプション項目の選択肢をゲーム内の表示順で保持します（定義元は `src/option_master.py`。起動時に定義どおりに入れ直されます）。
  - スコア保存時のオプション値の表記統一（例: `x3.5` → `3.5`、`ON大` → `ON 大`）と、スコア記録の修正画面の選択肢に使われます。
- **CSV エクスポート機能**:
  - メニューの「データ → CSVファイルを出力...」またはスコア履歴ダイアログの「CSVエクスポート...」から、SQLite のスコア管理テーブルと曲テーブルを JOIN して以下の 23 列の CSV ファイルを出力できます（「使用オプション」要約列は除外され、各個別オプション列が出力されます）：
  ```csv
  レベル,曲名,難易度区分,SCORE,COOL,GREAT,GOOD,BAD,COMBO,HI-SPEED,POP-KUN,GAUGE TYPE,GUIDE SE,RANDOM,JUDGE+,HIDDEN,SUDDEN,OJAMA1,OJAMA2,OJAMA1ずっと,OJAMA2ずっと,AUTO,プレー日時
  ```

### データベース管理ツール (`manage_db.py`)

コマンドラインから曲データのインポートや CSV のエクスポート・インポートを実行できます。

```bash
# popn_music_list.json から曲テーブルへインポート（UUID付与）
python manage_db.py import-music

# SQLite から CSV へエクスポート
python manage_db.py export-csv

# 既存 CSV から SQLite へインポート
python manage_db.py import-csv

# DB 統計情報の確認
python manage_db.py stats
```
